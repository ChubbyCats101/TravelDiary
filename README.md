# TravelDiary

แอปบันทึกการเดินทาง รองรับบัญชีผู้ใช้ เพิ่ม/แก้ไข/ลบทริป แนบรูป ปักหมุดบนแผนที่ ค้นหา และทริปโปรด

## การแจ้งเตือน

เปิด **โปรไฟล์ → การแจ้งเตือน** บน Android/iOS:

- **เตือนเฉพาะวันที่เลือก:** ใส่ข้อความ เลือกวันและเวลาในอนาคต ตั้งได้ 20 รายการ แก้ไขหรือยกเลิกได้ แตะการแจ้งเตือนเพื่อเปิดหน้าเพิ่มบันทึก
- **ย้อนความทรงจำ:** เปิดสวิตช์และเลือกเวลา อิงวันครบรอบวันที่เดินทาง รวมหลายทริปในวันเดียวกัน แตะเพื่อเปิดบันทึกหรือรายการความทรงจำ วันที่ 29 กุมภาพันธ์แจ้งเฉพาะปีอธิกสุรทิน
- **ทดสอบ:** มีปุ่มทดสอบทั้งสองแบบใน 3 วินาที การทดสอบความทรงจำจำลองข้อความจากวันครบรอบถัดไป

การตั้งค่าเก็บแยกบัญชีบนเครื่องนี้ ไม่ซิงก์ไปเครื่องอื่น ออกจากระบบจะยกเลิกการเตือนที่รอแจ้ง เข้าสู่ระบบและโหลดบันทึกสำเร็จจะตั้งรายการที่ยังไม่ถึงเวลาใหม่ หากแตะแจ้งเตือนขณะเซสชันหมดอายุ ให้เข้าสู่ระบบบัญชีเดิมก่อน

ตารางล่วงหน้ารวมสูงสุด 59 รายการ (สำรองอีกหนึ่งรายการสำหรับทดสอบ) โดยให้การเตือนที่ผู้ใช้สร้างมาก่อน แล้วเติมวันครบรอบที่ใกล้ที่สุดถึงสิ้นปีปัจจุบัน + 4 ตารางจะปรับเมื่อเข้าแอป กลับจากเบื้องหลัง หรือแก้ไข/ลบบันทึก จึงควรเปิดแอปเป็นระยะเพื่อเติมตารางในอนาคต การส่งจริงขึ้นกับสิทธิ์และการจัดการพลังงานของระบบ ไม่รับประกันตรงวินาที

ใช้ Local Notifications ไม่ต้องมีเซิร์ฟเวอร์ส่ง Push; SDK 57 ใช้เฉพาะ local API เพื่อเลี่ยงการเริ่ม remote push ของ Expo Go Android ทดสอบการส่งจริงและการแตะเปิดแอปบนมือถือด้วยขั้นตอนใน [NOTIFICATIONS_TESTING.md](docs/NOTIFICATIONS_TESTING.md)

## โครงสร้างไฟล์

```text
TravelDiary/
├── app/          หน้าจอและเส้นทางของ Expo Router
├── src/          โค้ดส่วนกลางของแอป
│   ├── components/  ส่วนประกอบหน้าจอและรูปแบบ UI
│   ├── constants/   ค่าคงที่ เช่น ตัวเลือกฟิลเตอร์รูป
│   ├── contexts/    สถานะบัญชีและรายการทริป
│   ├── hooks/       การทำงานของฟอร์ม
│   ├── services/    เชื่อม API รูปภาพ และตำแหน่ง
│   └── types/       รูปแบบข้อมูลและการตรวจสอบ
├── server/       API และฐานข้อมูลส่วนตัวใน .data/
├── tests/        ชุดทดสอบอัตโนมัติ
├── scripts/      เครื่องมือวัดประสิทธิภาพ
└── docs/         คู่มือทดสอบและรายงานผล
```

ไฟล์ตั้งค่า เช่น `package.json`, `app.json`, `tsconfig.json` และ `jest.config.cjs` อยู่ที่รากโปรเจกต์ตามเดิม ส่วน `node_modules/`, `.expo/` และ `.verification/` เป็น dependencies, ข้อมูลที่เครื่องมือสร้าง และหลักฐานการตรวจสอบ ไม่ใช่หน้าจอที่ต้องแก้ไข

## เริ่มใช้งาน

ใช้ Node.js 22.13+ และ Expo Go ที่รองรับ Expo SDK 57

```sh
npm ci
npm start
```

คำสั่งนี้เปิดทั้ง Expo และ API เชื่อมมือถือกับคอมพิวเตอร์บน Wi-Fi เดียวกัน แล้วสแกน QR ด้วย Expo Go โดยเปิดเซิร์ฟเวอร์ค้างไว้

แอปหา IP ของ API จาก Expo อัตโนมัติ หรือกำหนดเองด้วย `EXPO_PUBLIC_API_URL`

## Performance

วัดบน Samsung SM-A556E / Android 16 ผ่าน Expo Go (25 ก.ย. 2569) หลังรีเซ็ตสถิติและให้ผู้ใช้ทดลองใช้งาน:

| ตัวชี้วัด | ผล |
| --- | ---: |
| เฟรมที่วัดได้ | 1,342 |
| เฟรมกระตุก (Janky frames) | 39 เฟรม (2.91%) |
| เวลาเฟรม Median / P95 | 9 / 19 ms |
| หน่วยความจำ PSS หลังทดสอบ | 684.1 MiB |

เป็นค่าของทั้งโปรเซส Expo Go ในช่วงเก็บประมาณ 85 วินาที รวมช่วงรอ ไม่ใช่ release build หรือ FPS เฉลี่ย ยังไม่ได้วัดเวลาเปิดแอป ดู [รายละเอียดการวัด](docs/PERFORMANCE_DEVICE.md)

ผลวัด API บนคอมพิวเตอร์ผ่าน localhost ใช้ SQLite บนดิสก์และข้อมูลทดสอบไม่มีรูป (25 ก.ย. 2569):

| งาน | Median | P95 |
| --- | ---: | ---: |
| Login | 60.97 ms | 69.04 ms |
| โหลด 100 ทริป | 1.96 ms | 3.14 ms |
| แก้ไขทริป | 10.98 ms | 12.86 ms |
| สร้างทริป | 10.33 ms | 12.79 ms |
| ลบทริป | 10.15 ms | 13.43 ms |

วัดทีละคำขอ 50 ครั้งหลัง warm-up 5 ครั้ง (Login 10 ครั้ง หลัง warm-up 2 ครั้ง) รวมรับและอ่าน JSON; P95 คือเวลาที่ 95% ของคำขอไม่เกิน ค่านี้ไม่รวมเครือข่ายมือถือหรือการแสดงหน้าจอ

รันวัดซ้ำด้วย `node scripts/benchmark.mjs` ดูข้อมูลเครื่องและผลดิบใน [PERFORMANCE_RESULTS.json](docs/PERFORMANCE_RESULTS.json) ใช้ฐานข้อมูลชั่วคราวแยกจากข้อมูลจริง
