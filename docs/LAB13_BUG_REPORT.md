# Bug report — TD-13-001

วันที่: 25 กันยายน 2569 · ระดับ: ปานกลาง · สถานะ: แก้ไขแล้ว

**ปัญหา:** เมื่อบันทึกหรือลบทริปได้รับ HTTP 401 แอปยังเก็บ session และแสดงข้อมูลส่วนตัว แม้ API จะปฏิเสธ token แล้ว

## วิธีทำซ้ำด้วย test

1. โหลด session ทดสอบและรายการทริปผ่าน AuthProvider/TripsProvider จริง
2. Mock saveTrip หรือ deleteTrip ให้ตอบ `ApiError(401)`
3. เรียกบันทึกหรือลบ แล้วตรวจ session

**ก่อนแก้:** session ยังอยู่ ทำให้ regression tests ไม่ผ่าน 2 กรณี

**ผลที่ควรได้:** ล้าง session, SecureStore และรายการส่วนตัว

## สาเหตุและการแก้ไข

`TripsContext.tsx` จัดการ 401 เฉพาะตอนโหลดรายการ แต่ไม่จัดการตอนบันทึก/ลบ จึงเพิ่มการเรียก expire ในสองเส้นทางนี้ โดยตรวจว่าเป็น token ของบัญชีปัจจุบันก่อนล้าง

## ผลยืนยัน

รัน `npx jest --runInBand tests/diary.test.tsx` ผ่าน 9/9 รวมกรณี 401 ตอนบันทึก/ลบ, network error ต้องไม่ออกจากระบบ และคำตอบ 401 ของบัญชีเก่าต้องไม่ล้างบัญชีใหม่ ทั้งโปรเจกต์ผ่าน 25/25 tests

หลักฐานก่อนแก้: `.verification/lab13-regression-before.txt` ทดสอบด้วย mocks ยังไม่ได้ยืนยันบนมือถือจริง

**วิธีหลีกเลี่ยงก่อนอัปเดต:** ออกจากระบบแล้วเข้าสู่ระบบใหม่เมื่อพบข้อความเซสชันหมดอายุ
